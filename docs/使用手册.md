## 先理解四个概念

### 1. 通知入口：谁把事情告诉 EasyNotice

入口可以理解为一个专属收件地址。Lucky、OpenWrt、MDC-NG 等每个应用都应该有自己的入口，这样 EasyNotice 才知道通知来自哪里，也能分别设置样式和路线。

入口地址包含随机密钥，应当像密码一样保管。更换入口密钥后，原地址立即失效，原应用里也要换成新地址。

### 2. 通知出口：EasyNotice 最后把消息发到哪里

出口是企业微信应用、企业微信群机器人、Telegram Bot 或 Bark。一个出口配置一次，就能被多个入口共同使用。

### 3. 发送路线：失败后补位，还是全部发送

- **失败后按顺序补位**：先发第一个；失败才发第二个；适合“企微应用 → 企微机器人”。
- **每个出口都发送**：每条通知会尝试所有已勾选出口；适合同时通知不同的人或不同设备。

### 4. 样式规则：同一个应用的不同事件长得不一样

规则可以按标题、正文、事件类型或严重级别匹配，再改写标题、正文、图片和链接。例如让“下载完成”用绿色图片，“刮削失败”用红色图片。

## 部署 EasyNotice

### 用 Docker Compose 部署

在 NAS 上新建一个空目录，例如 `easynotice`，把仓库中的 [docker-compose.yml](../docker-compose.yml) 放进去，或新建以下文件：

```yaml
services:
  easynotice:
    image: ghcr.io/xudong7587/easynotice:latest
    container_name: easynotice
    restart: unless-stopped
    ports:
      - "18088:18088"
    environment:
      TZ: Asia/Shanghai
      HOST: 0.0.0.0
      PORT: 18088
    volumes:
      - ./data:/app/data
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://127.0.0.1:18088/health').then(r=>{if(!r.ok)process.exit(1)}).catch(()=>process.exit(1))"]
      interval: 30s
      timeout: 5s
      retries: 3
      start_period: 15s
```

在这个目录中运行：

```bash
docker compose config
docker compose pull
docker compose up -d
```

`config` 用来提前发现缩进或字段错误；`pull` 确保首次部署使用当前镜像。

随后打开：

```text
http://NAS的局域网IP:18088
```

例如 NAS 是 `192.168.1.10`，地址就是 `http://192.168.1.10:18088`。

### 用 NAS 图形界面部署

不同 NAS 的按钮名称略有区别，但要填写的内容相同：

| 项目 | 填写内容 |
| --- | --- |
| 镜像 | `ghcr.io/xudong7587/easynotice:latest` |
| 容器名 | `easynotice` |
| 宿主机端口 | `18088`，也可改成一个未占用端口 |
| 容器端口 | `18088` |
| 数据目录 | NAS 上的持久目录，例如 `/volume1/docker/easynotice/data` |
| 容器内目录 | `/app/data`，读写 |
| 环境变量 | `TZ=Asia/Shanghai`、`HOST=0.0.0.0`、`PORT=18088` |
| 重启策略 | `unless-stopped` 或“除非手动停止” |

不要额外填写 `user:`，当前镜像也不支持 `PUID`、`PGID`。启动脚本会先整理 `/app/data` 的所有权，再以 UID `1000` 运行服务。

### 修改外部端口

容器内端口保持 `18088`。如果 NAS 的 18088 已被占用，可以只改冒号左侧：

```yaml
ports:
  - "28088:18088"
```

此时浏览器访问 `http://NAS局域网IP:28088`，首次设置中的访问地址也要写 28088。下文宿主机和局域网测试命令都按默认外部端口 18088 举例；如果你改过映射，请把这些地址换成冒号左侧的端口。只有容器内部健康检查和 Docker 共享网络中的服务端口继续使用 18088。

### 为什么健康检查里可以用 127.0.0.1

Compose 健康检查是在 EasyNotice 容器**内部**执行，所以 `127.0.0.1:18088` 在那里是正确的。浏览器、OpenWrt 和其他容器不在 EasyNotice 容器内部，不能照抄这个地址。

### 第一次启动遇到 EACCES

如果日志显示：

```text
EACCES: permission denied, mkdir '/app/data/uploads'
```

按以下顺序处理：

1. 执行 `docker compose pull`，确认已经拉取最新镜像。
2. 执行 `docker compose up -d --force-recreate`，不要只点“重启”。
3. 确认挂载目录不是只读；启动脚本需要能递归调整所有权，服务进程需要以 UID `1000` 读写。
4. 不要使用 `chmod -R 777`；这会扩大风险，也不一定能解决 NFS 映射问题。
5. NFS root-squash、SMB/CIFS 和特殊 ACL 可能让启动脚本的 `chown` 失败；优先改用 NAS 本地文件系统，或使用有独立备份方案的 Docker 命名卷。

### 确认服务已经运行

```bash
docker compose ps
docker compose logs --tail=100 easynotice
```

还可以在 NAS 本机测试：

```bash
curl http://127.0.0.1:18088/health
```

局域网另一台设备则测试：

```bash
curl http://192.168.1.10:18088/health
```

把示例 IP 换成你的 NAS 地址。如果容器健康但第二条失败，请看[局域网打不开但反向代理能打开](#局域网打不开但反向代理能打开)。

### 环境变量说明

普通部署保持官方 Compose 即可。需要调整时再使用下表：

| 变量 | 默认或建议值 | 作用 |
| --- | --- | --- |
| `TZ` | `Asia/Shanghai` | 日志和页面使用的时区 |
| `HOST` | `0.0.0.0` | 监听所有容器网卡；不要改成 `127.0.0.1` |
| `PORT` | `18088` | 容器内部端口，通常不要改 |
| `EASYNOTICE_DATA_DIR` | 保持 `/app/data` | 数据库、主密钥和图片所在目录；普通用户不要修改 |
| `EASYNOTICE_COOKIE_SECURE` | 默认关闭 | 浏览器始终经 HTTPS 访问时设为 `true` |
| `EASYNOTICE_SECRET_FILE` | 无 | 高级用法：从只读文件加载安装主密钥 |
| `EASYNOTICE_SECRET` | 无，不推荐 | 直接从环境变量加载主密钥，容易被容器检查信息暴露 |

如果确实把 `EASYNOTICE_DATA_DIR` 改成其他容器路径，卷的容器端目标也必须同步修改，例如 `宿主目录:/data` 对应 `EASYNOTICE_DATA_DIR=/data`；否则数据会写进容器临时层，重建后丢失。EasyNotice 没有 `PUID`、`PGID` 变量，也不需要特权模式、Host 网络或 Docker Socket。

## 跑通第一条通知

建议先跑通最简单的一条链路，再配置图片、规则和多个出口。

### 第一步：创建管理密码

首次打开页面时创建至少 8 位密码。不要与 NAS 管理员密码相同。

### 第二步：填写其他容器访问地址

这里不是问“浏览器现在显示什么”，而是问：**发送通知的应用怎样找到 EasyNotice。**

| 来源在哪里 | 建议填写 |
| --- | --- |
| OpenWrt、NAS 上另一个应用、局域网设备 | `http://NAS局域网IP:18088` |
| 与 EasyNotice 位于同一个 Docker 网络 | `http://easynotice:18088`，前提是来源能解析这个服务名 |
| 来源在公网，或 Bark 需要访问本地素材 | 可公网访问的 HTTPS 反向代理地址 |
| 只在当前浏览器使用 | 仍建议填写 NAS 局域网地址，不要填 `localhost` |

这个地址会用于生成入口地址、Bark 的本地素材签名地址和企业微信回调地址。修改它只会改变 EasyNotice 页面以后显示的复制内容，已经粘贴到 Lucky、OpenWrt 等原应用里的旧地址不会自动更新。

### 第三步：先添加一个通知出口

打开“通知出口”。想最快成功可以先选：

- 企业微信群机器人：企业微信用户最简单，固定纯文字。
- Bark：iPhone 用户简单直接。

保存后点击“文字预览”或“图文预览”。手机或群里收到带“测试”标记的消息，说明 EasyNotice 已经能向外发送。

### 第四步：添加通知入口

打开“通知入口”并选择原应用。给入口起一个容易识别的名字，例如“Lucky 主路由”，勾选刚才的出口，然后创建。

### 第五步：复制到原应用

创建完成后按页面说明复制：

- 一般应用复制接口地址、POST、`application/json` 和请求体。
- OpenWrt PushBot 必须复制完整大段配置，不能拆开。
- 只有 URL 输入框时，可以先粘贴接口地址并发送测试；必要时使用通用入口。

### 第六步：看通知记录

在原应用发送测试或触发真实事件，然后打开“通知记录”：

- 有新记录：入口已经通，继续看出口投递详情。
- 没有记录：检查原应用中的地址、网络、请求方式和入口是否已停用。
- 记录显示“已送达”：整条链路完成。
- 记录显示“备用送达”：前面的出口失败，后面的出口成功补位。

## 配置通知出口

### 先看四种渠道的区别

| 渠道 | 文字 | 本地图片 | 公网图片 | 点击链接 | 关键限制 |
| --- | --- | --- | --- | --- | --- |
| 企业微信应用 | 支持 | 上传为企微图文 | 发送企微图文 | 支持 | 需要企业可信公网 IP；本地图片不超过 2 MB |
| 企业微信群机器人 | 支持 | 忽略 | 忽略 | 以文字链接附在正文后 | 固定纯文字，约 2048 个 UTF-8 字节 |
| Telegram Bot | 支持 | 直接上传 | 发送照片 | 当前不附加 | 图片说明约 1024 字符，纯文字约 4096 字符 |
| Bark | 支持 | 转成签名公网地址作为图标 | 作为图标 | 支持 | Bark 服务端必须能访问图片地址 |

### 企业微信群机器人

适合先跑通通知，也适合放在企微应用后面补位。

1. 在企业微信群中打开群设置，添加“群机器人”。
2. 创建机器人并复制 Webhook 地址。
3. 地址通常形如 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=一串内容`。
4. EasyNotice 只填写 `key=` 后面的内容，不要填写整个地址。
5. 保存后点击“文字预览”。

机器人始终发送标题、正文、来源名称，以及通知自带的文字链接。它不会发送入口图片、规则图片或默认封面，通常也不依赖企业可信 IP。

### 企业微信应用

适合正式的图文通知和点击链接。

准备以下内容：

- 企业 ID（CorpID）：企业微信“我的企业 → 企业信息”。
- AgentId：自建应用详情页中的数字 ID。
- 应用 Secret：必须使用这个自建应用的 Secret，不要使用通讯录 Secret。
- 接收成员：默认 `@all` 表示应用可见范围内的成员；也可填写成员账号。
- 接收部门：可选，填写部门 ID。

配置步骤：

1. 在企业微信管理后台创建自建应用，并设置可见范围。
2. 在 EasyNotice 中填写 CorpID、AgentId、Secret 和接收范围。
3. 在企微后台进入“应用管理 → 自建应用 → 开发者接口 → 企业可信 IP”。
4. 添加 EasyNotice 访问互联网时使用的**公网出口 IP**，不是 `192.168.x.x` 局域网地址。
5. 保存出口并发送图文预览。
6. 若返回 `60020`，错误详情会显示企微识别到的公网 IP；把它加入可信 IP 后重试。

发送形式由内容决定：

- 本地素材：先上传到企业微信，再发送单条图文。
- 公网图片：发送 `news` 图文。
- 没有图片但有链接：发送 `textcard`。
- 没有图片和链接：发送纯文字。

“企业可信 IP”和“接收消息与事件回调”不是同一件事。主动发送必须处理可信 IP；回调是可选功能，只在你需要企微把成员消息或事件推回 EasyNotice 时启用。当前回调只完成验签、解密和留档，不会自动回复成员。

如果启用回调：先保存出口，再把页面生成的回调 URL、Token 和 43 位 EncodingAESKey 填入企微“接收消息 → 设置 API 接收”。该地址通常需要公网可访问的 HTTPS 443 端口。

### Telegram Bot

1. 在 Telegram 找到官方 `@BotFather`，发送 `/newbot` 并按提示创建 Bot。
2. 保存 Bot Token；它等同密码，不要公开。
3. 先私聊 Bot 并发送 `/start`，或把 Bot 加入目标群并发送一条消息。
4. 浏览器访问 `https://api.telegram.org/bot你的Token/getUpdates`。
5. 在返回内容中找到 `message.chat.id`，填入 Chat ID。群组和频道通常是带负号的数字。
6. API 地址通常保持 `https://api.telegram.org`。
7. 保存后发送图文预览。

如果目标是频道，Bot 通常需要被设为管理员。中国大陆网络无法直连 Telegram API 时，只使用自己信任的反向代理；公共代理可以看到 Token 和消息内容。

勾选“静默发送”后，消息会到达但不播放提示音。当前版本可以发送文字和图片，但不会把规则中的点击链接附到 Telegram 消息里。

### Bark

Bark 是 iPhone 上的个人推送工具。

1. 在 iPhone 安装并打开 Bark，允许系统通知。
2. 首页会显示专属测试地址，例如 `https://api.day.app/设备Key/测试`。
3. 可以把完整地址直接粘贴到 EasyNotice 的 Bark Key，页面会自动拆出服务器和设备 Key；也可以只填 Key。
4. 官方服务保留默认 `https://api.day.app`；自建 Bark Server 时填写自己的地址。
5. 可设置分组、铃声和时效级别。
6. 保存并发送图文预览。

时效级别：

- 普通：立即亮屏并显示。
- 时效通知：可穿过专注模式，是否生效还取决于 iPhone 设置。
- 静默：只进入通知中心。

Bark 的图片是通知图标，不是大图消息。本地素材会被 EasyNotice 转成签名 URL；“其他容器访问地址”必须能被 Bark 服务端从公网访问，图标才会显示。只在局域网可访问的 `192.168.x.x` 地址无法被官方 Bark 服务拉取。

### 编辑和停用出口

- 编辑已保存的出口时，密钥字段留空表示保留原值。
- 停用出口会把它从所有入口路线中移除。
- 之后重新编辑保存可以重新启用出口，但原来的入口路线不会自动恢复；要逐个入口重新勾选。
- 永久删除前必须先停用。

### 四种测试的区别

| 测试 | 在哪里 | 验证什么 | 是否生成通知记录 |
| --- | --- | --- | --- |
| 出口消息预览 | 通知出口卡片 | 这个渠道的凭证和网络能否发送 | 否 |
| 指定出口来源预览 | 入口详情中某个出口右侧“预览” | 这个来源的测试内容在指定渠道如何显示 | 否 |
| 整链路测试预览 | 入口详情顶部 | 规则、路线、重试和补位是否工作 | 是 |
| 原应用真实测试 | Lucky、OpenWrt 等原应用 | 从原应用到手机的真实全链路 | 是 |

内置预览样例的标题会明确标注“测试”；样式规则仍可能改写标题。没有匹配图片时，图文预览使用内置封面；这不会改变真实通知的图片行为。

## 配置通知入口

### 创建入口的通用流程

1. 打开“通知入口”，点击“添加通知入口”。
2. 搜索并选择原应用；不知道选什么时用“通用 Webhook”。
3. 给入口命名，建议包含设备或实例，例如“Lucky 主路由”“MDC-NG 家庭库”。
4. 选择“按顺序补位”或“所有渠道都发送”。
5. 勾选出口；补位模式中的勾选顺序就是发送顺序，之后可在详情页调整。
6. 创建入口并复制页面生成的内容。
7. 在原应用发送测试，再到通知记录确认。

原应用显示“Webhook 调用成功”只说明它收到了 EasyNotice 的 HTTP 200 响应。EasyNotice 会先把通知持久化再异步发送，因此最终结果仍要看通知记录。

入口可以停用，停用后旧地址立即停止接收，但入口和既有配置仍会保留并可查看。当前页面没有“重新启用”按钮；不再需要时可以永久删除，因此停用前请谨慎确认。永久删除入口会一并删除相关规则、通知记录和投递明细，无法恢复。

### Lucky

EasyNotice 会按通知场景生成不同请求体。先在入口页面勾选需要的场景，再逐张复制到 Lucky 对应位置。

通用填写方式：

- 接口地址：复制 EasyNotice 生成的地址。
- 请求方法：`POST`。
- 请求头或内容类型：`application/json`。
- 请求体：完整复制对应卡片里的 JSON。
- “接口调用成功包含的字符串”：填写 `success`。
- 重试次数：可按需要设置，EasyNotice 自己对出口还会再尝试两次。

| 场景 | Lucky 中的位置 | 类型 | 需要知道 |
| --- | --- | --- | --- |
| DDNS / 公网 IP 变化 | 动态域名 → DDNS 任务 → 编辑 → Webhook | 原生触发 | 可直接使用 `{time}`、`{ipAddr}` |
| STUN 公网地址变化 | STUN 规则或 STUN 全局 Webhook | 原生触发 | 局部变量通常保留 `#{变量名}` 写法 |
| 设备上线、离线 | 网络唤醒设备的上下线 Webhook | 原生触发 | 把模板里的设备名称换成真实名称 |
| 计划任务结果 | 计划任务中，在被报告任务后添加 CallWeb | 计划任务 | 模板中的任务名要与 Lucky 完全一致 |
| 端口转发状态 | 定时计划任务 + CallWeb | 状态报告 | `on` 只表示规则开启，不代表端口真的可连通 |
| Web 服务状态 | 定时计划任务 + CallWeb | 状态报告 | 只报告 Lucky 规则开关状态，不是健康检查 |
| 证书续签结果 | SSL 证书模块 | 暂不可直接接 | Lucky 没有可直接复制的原生续签完成回调 |

如果 Lucky 不断提示 `connection refused`，请在所有 DDNS、STUN 任务和全局 Webhook 中查找旧地址。只关闭错误弹窗不会停止旧任务继续重试。

### OpenWrt / iStoreOS 全能推送 PushBot

这个入口与通用 Webhook 不同。PushBot 的设置页只有一个“自定义推送”大文本框，没有单独 URL 输入框，这是程序本身的设计。

正确步骤：

1. 打开 OpenWrt：服务 → 全能推送 → 基本设置。
2. 勾选“启用”。
3. 在“推送模式”选择“自定义推送”。
4. 回到 EasyNotice 的 OpenWrt 入口，点击“复制整段配置”。
5. 清空 PushBot 大文本框中的旧示例或旧配置。
6. 把复制内容完整粘贴一次；不要拆分 URL、请求头和请求体，也不要只替换其中几行。
7. 点击“保存并应用”。
8. 点击大文本框下方的“发送测试”。
9. 回到 EasyNotice 的通知记录确认。
10. 跑通后再到 PushBot 的“推送内容”页勾选公网 IP、设备上下线、负载温度、Web/SSH 登录等事件。

生成的整段配置已经包含入口地址、POST JSON、标题、正文和旧版 PushBot 需要的格式字段。以后需要重新复制时，打开“通知入口 → 这个 OpenWrt 入口”即可；配置会持续保存在 EasyNotice 中。

如果路由器无法发送，先确认 OpenWrt 自己能解析并访问生成地址。浏览器能打开域名，不代表路由器的 DNS、回环或防火墙也能访问。

### MoviePilot、MediaIndex、NASTool

- **MoviePilot**：安装官方 WebHook 插件，在插件设置中把第三方地址填写为 EasyNotice 入口地址。不要把 MoviePilot 管理员 API Token 填到 EasyNotice。
- **MediaIndex**：只有当前版本提供“自定义 Webhook / 通知 URL”时才能直接接入。选择 POST、JSON 并粘贴入口地址。
- **NASTool**：官方内置通知主要面向指定渠道；需要支持自定义 Webhook 的插件或转发组件。

如果设置页只能填写“企微机器人 Key”等专用 Key，不能修改完整 URL，这个版本通常不能直接接入 EasyNotice。不要把 EasyNotice 的整段地址硬塞进 Key 输入框。

不同版本发送字段可能不同。先触发一次真实订阅、下载、整理或入库事件，再从通知记录查看识别结果并添加规则。

### MDC-NG、Emby、Jellyfin、Plex

MDC-NG：

1. 在通知设置中新增 Endpoint。
2. 名称自定义，例如 `EasyNotice`。
3. 请求方式选择 `POST`。
4. URL 粘贴入口地址。
5. 请求头/内容类型使用 `application/json`。
6. Body 模板复制 EasyNotice 页面给出的 JSON；保留 MDC-NG 的 `{{ event }}`、`{{ title }}`、`{{ poster }}` 等变量。
7. 点击连接测试，再触发一次真实刮削成功或失败事件。

Emby 需要先安装 Webhooks 通知插件，再到通知设置中新增 Webhook。它会自己生成请求体，不要粘贴 MDC-NG 模板。Jellyfin、Plex 或其他影音服务同理：找到 Webhook / Notifications，优先选 POST 和 JSON。

MDC-NG 的 `poster` 会被自动识别为图片，`error_message` 会被识别为正文。首次真实通知后再决定是否按成功、失败、分类等字段覆盖图片。

### Uptime Kuma

1. 打开 Uptime Kuma 的通知设置。
2. 新建 Webhook 类型通知。
3. 粘贴 EasyNotice 入口地址。
4. 请求体格式选择 JSON。
5. 使用入口页面给出的模板并发送测试。

不同版本提供的模板字段略有差异。EasyNotice 会尝试识别 `msg`、`monitorJSON.name`、`heartbeatJSON.status` 等常见字段。

### Watchtower / Shoutrrr

在通知 URL 或 Webhook URL 中粘贴入口地址；可以选格式时优先 JSON。只提供一个 URL 输入框的程序，也可以用 GET 查询参数：

```text
https://你的EasyNotice地址/hook/随机令牌?title=Docker更新&content=镜像更新完成
```

先发一次测试，确认实际收到的字段，再决定是否需要内容规则。

### 通用 Webhook

不知道原应用格式时先使用通用入口。它会自动从常见字段里寻找标题、正文、事件、图片和链接，也能接收 JSON、表单、纯文本、XML 文本或 URL 查询参数。

最简单的 JSON：

```json
{
  "title": "测试标题",
  "content": "这是一条真实接入测试",
  "event": "test",
  "image": "https://example.com/image.jpg",
  "url": "https://example.com/detail"
}
```

如果识别结果不符合预期，打开通知记录查看原始数据：可以调整原应用的字段，或用规则重写展示内容。

### 不知道怎么选时使用 AI 助手

AI 助手是可选功能。配置后可以输入项目名、粘贴说明或上传配置页截图，它会推荐一个**已有预设**、入口名称和填写建议。

它不会：

- 登录或修改原应用；
- 自动创建入口；
- 把 AI 返回的自定义请求头和请求体直接写入系统；
- 参与任何真实通知的接收和发送。

AI 可能判断错误，最终仍以原项目文档、EasyNotice 收到的真实记录和发送测试为准。上传截图前遮住 Token、Cookie、Webhook Key、公网 IP 和个人信息。

## 设置补位和广播

在入口详情右侧“出口设置”中勾选出口并选择模式。

### 失败后按顺序补位

使用上下箭头调整顺序，然后点击“保存出口设置”。每个出口最多尝试两次，两次之间会短暂等待；单次外部请求最长等待约 12 秒。

某个出口成功后：

- 后续出口不会再发送；
- 通知记录会把它们显示为“跳过”；
- “跳过”不是故障，而是前一个出口已经完成。

推荐顺序：

1. 企业微信应用：正式图文。
2. 企业微信群机器人：不依赖应用可信 IP的纯文字补位。
3. Telegram 或 Bark：可选的第二层补位。

如果主渠道失败、备用渠道成功，整条通知显示“备用送达”。

### 每个出口都发送

EasyNotice 会尝试每个已勾选出口。全部成功时显示“已送达”；有成功也有失败时显示“备用送达/部分成功”；全部失败时显示“失败”。

### 修改和停用的影响

- 调整路线后一定要点击“保存出口设置”。
- 停用出口会从所有入口路线中移除；重新启用不会自动恢复原顺序。
- 没有勾选任何出口时，Webhook 仍可能进入记录，但最终会失败并提示没有可用路由。

## 自定义标题正文图片和链接

在入口详情点击“添加样式规则”。

### 第一条匹配规则生效

规则先按优先级数字从小到大匹配；数字相同时，较早创建的规则先匹配。**只应用第一条符合条件的规则**，不会把多条规则叠加。

建议给更具体的规则较小数字，最后放一条“所有通知”的通用规则。例如：

| 优先级 | 条件 | 用途 |
| --- | --- | --- |
| 10 | 严重级别等于 `error` | 失败通知用红色图片 |
| 20 | 事件类型等于 `finished` | 完成通知用绿色图片 |
| 100 | 所有通知 | 统一补充来源名称 |

### 可以检查什么

- 标题或正文任意位置；
- 标题；
- 正文；
- 事件类型；
- 严重级别：`info`、`success`、`warning`、`error`；
- 所有通知。

条件支持“包含”“等于”“正则表达式”“总是”。无效正则不会让通知失败，只会视为不匹配；不熟悉正则时优先用“包含”。

### 模板怎么写

模板只做安全的变量替换，不运行 JavaScript 或 Jinja2。常用变量：

```text
原标题：{{ title }}
原正文：{{ body }}
事件类型：{{ eventType }}
严重级别：{{ severity }}
原始 JSON 字段：{{ data.number }}、{{ monitorJSON.name }}
```

示例标题：

```text
[失败] {{ title }}
```

留空表示沿用原内容。请确保链接模板最终生成有效的 `http://` 或 `https://` 地址；当前系统不会替你验证规则链接，错误地址可能导致渠道发送失败。

### 图片从哪里来

规则填写公网图片地址时，会覆盖原应用传来的公网图片；没有规则图片时沿用原应用的 `image`、`poster`、`thumb`、`cover` 等字段。规则选择本地素材时，各渠道按自己的能力处理，不宜假设所有渠道都有完全相同的优先级。

真实 Webhook 如果没有图片，EasyNotice 不会自动加默认封面。默认封面只在测试预览缺少图片时出现。

不同出口会按自己的能力处理：

- 企业微信应用：规则本地素材优先直接上传；公网图片生成图文。
- 企业微信群机器人：忽略所有图片，保持纯文字。
- Telegram：规则本地素材优先直接上传；公网图片作为照片发送。
- Bark：把图片当图标，URL 必须能被 Bark 服务端访问。若入口同时自带公网图片，当前会优先使用它而不是规则中的本地素材；需要确定图标时可在规则中使用公网图片地址，或让入口不再发送图片字段。

## 管理图片素材

素材库支持：PNG、JPEG、WebP、GIF；单文件最多 4 MB。企业微信应用上传本地图片时另有 2 MB 限制，因此要发企微图文时建议把图片控制在 2 MB 以内。

使用方法：

1. 在“图片素材”上传一次。
2. 在不同入口的样式规则中重复选择它。
3. 也可以在创建规则时直接上传新图片。

删除素材后，引用它的规则会失去本地图片，通知会回到原应用图片或无图片状态。删除前先检查哪些规则仍在使用。

本地素材的管理地址需要登录；当 Bark 等外部服务需要读取时，EasyNotice 会按“其他容器访问地址”生成带签名的公开地址。签名地址不会自动过期，敏感图片不要作为公网素材使用。

## 看懂通知记录

### 状态含义

| 状态 | 含义 |
| --- | --- |
| 等待发送 | 已持久化，正在等待后台处理 |
| 正在发送 | 正在执行规则后的路线 |
| 已送达 | 路线按当前模式成功完成 |
| 备用送达 | 主出口失败但后续出口成功，或广播时部分成功 |
| 失败 | 没有任何出口成功，或没有配置可用出口 |

### 一条出口为什么会出现两次失败

EasyNotice 会对同一出口最多尝试两次，所以详情里可能看到“第 1 次尝试”和“第 2 次尝试”。这不是重复通知，而是自动重试。

### 详情里能看到什么

- 识别后的标题、正文、事件类型和严重级别；
- 命中的样式规则；
- 每个出口的顺序、尝试次数、耗时、HTTP 状态和错误；
- 脱敏后的原始 Webhook；
- 请求 ID，用于对照原应用或代理日志。

标题、正文和来源可以搜索，也可按入口和状态筛选。

### 重新发送

只有已经结束的通知才能重新发送。点击后，通知会按**当前**路线和当前出口配置重新进入队列，既有投递历史会保留并追加新的尝试记录。

## 系统设置与 AI 助手

### 应用名称

此项会保存为基础设置，但当前界面品牌仍以 EasyNotice 为主，不要把它理解成完整的白标或全站改名功能。

### 其他容器访问地址

它决定新生成的入口地址、企微回调地址和公开素材地址。填写一个对通知来源真正可达的 URL，不要填 `localhost`。

修改后：

- 页面以后显示的新复制内容会改变；
- 已经粘贴到原应用的旧地址不会自动改变；
- 入口随机令牌和路径不变时，可以在原应用中只替换主机名和端口；
- Bark 图片、企微回调等外部访问能力取决于新地址是否真的可达，不是保存设置后就自动打通。

### AI 接口

填写 OpenAI 兼容的接口根地址、模型名和 API Key。EasyNotice 实际调用 `/chat/completions`；截图分析还要求接口支持 `image_url` 多模态内容。

AI Key 会加密保存，编辑时留空表示保留原值。项目说明和截图会发送到你配置的 AI 服务；上传前请打码。

### 修改管理密码

新密码至少 8 位。修改成功后会注销所有设备的现有会话，需要重新登录。当前没有邮件找回密码功能，请妥善保管密码和数据备份。

## 高级 Webhook 接入

普通用户优先复制入口页面生成的内容。本节用于原应用没有现成预设时排查。

### 接口地址

新版地址：

```text
https://你的EasyNotice地址/hook/随机令牌
```

兼容旧版地址：

```text
https://你的EasyNotice地址/api/v1/notify/入口名?token=随机令牌
```

新版随机令牌已经在路径里，无需再加请求头。兼容地址也可以通过以下任一方式提供令牌：

```text
Authorization: Bearer 随机令牌
X-EasyNotice-Token: 随机令牌
```

每个入口可接受 GET、POST 及其他 HTTP 方法。JSON 请求体上限为 2 MB；图片不要直接塞成 Base64 JSON，使用公网 URL 或素材库。

### POST JSON

```bash
curl -X POST "http://192.168.1.10:18088/hook/随机令牌" \
  -H "Content-Type: application/json" \
  -d '{"title":"测试标题","content":"测试正文","event":"test"}'
```

成功响应中的 `success: true` 表示 EasyNotice 已接收入队，同时会返回识别出的标题、事件类型、严重级别和命中规则。它不代表下游出口已经送达。

### GET 查询参数

```text
http://192.168.1.10:18088/hook/随机令牌?title=公网IP更新&content=地址已经变化&event=ip_changed
```

### 表单、纯文本和 XML

如果程序只能发送表单或纯文本，EasyNotice 也能接收。纯文本会作为通知正文；XML 暂不做完整 XML 结构映射，而是作为文本内容接收。第一次发送后从通知记录检查识别结果。

### 自动识别字段

| 内容 | 常见字段示例 |
| --- | --- |
| 标题 | `title`、`subject`、`name`、`data.title`、`monitorJSON.name` |
| 正文 | `content`、`body`、`message`、`msg`、`error_message` |
| 事件 | `event`、`event_type`、`eventType`、`status` |
| 图片 | `image`、`image_url`、`poster`、`thumb`、`cover` |
| 链接 | `url`、`link`、`detail_url`、`data.url` |
| 严重级别 | `severity`、`level`、`priority` |

错误、失败、离线等关键词通常推断为 `error`；警告、过期推断为 `warning`；成功、完成、上线、恢复推断为 `success`；其他为 `info`。

标题最多保留 200 个字符，正文最多 10,000 个字符，事件类型最多 120 个字符。从真实 Webhook 自动识别出的外部图片和链接只接受 HTTP 或 HTTPS 地址；此外兼容 EasyNotice 自身的 `/api/assets/…` 素材路径。规则链接模板请自行保证格式正确。

## 更新备份与恢复

### data 目录里有什么

使用官方目录挂载和自动主密钥时，整个持久状态都在 `/app/data` 对应的宿主机目录：

```text
data/
├── .installation-secret
├── easynotice.db
├── easynotice.db-wal      # 运行时可能出现
├── easynotice.db-shm      # 运行时可能出现
└── uploads/
```

默认模式下，`.installation-secret` 和数据库缺一不可。只备份数据库会导致企业微信 Secret、机器人 Key、Telegram Token、Bark Key、AI Key、入口令牌等加密内容无法恢复。

如果配置了 `EASYNOTICE_SECRET_FILE`，程序会优先使用容器外的主密钥文件，data 中可能没有有效的 `.installation-secret`。此时必须另外备份该文件和它的挂载配置；恢复时保持原内容、原挂载路径，并确保 UID `1000` 可读。

### 一致备份

1. 先在通知记录确认没有“等待发送”或“正在发送”。
2. 停止容器。
3. 复制完整 `data` 目录，包括隐藏文件；建议同时备份 Compose 文件。使用外置主密钥时，再备份原 secret 文件和挂载配置。
4. 重新启动容器。

命令示例：

```bash
docker compose stop
sudo tar -czf ../easynotice-backup-$(date +%F).tar.gz docker-compose.yml data
docker compose start
```

这个命令只适用于 `./data:/app/data` 这类宿主机目录挂载，并应由有权读取 UID 1000、0700/0600 文件的管理员或 root 执行。使用 Docker 命名卷时，`tar data` 不会包含卷内真实数据；应在停止容器后使用 NAS 或 Docker 的卷备份/导出功能，并检查备份中确实存在数据库、uploads 和主密钥。

图形界面用户：停止容器 → 使用有足够权限的文件管理器 → 开启“显示隐藏文件” → 确认完整复制 data、Compose，以及可选的外置 secret → 再启动。不要只看到目录名就假定内容已经复制成功。

备份同时包含密文和解密主密钥，应放在加密磁盘或受控位置，不能上传到公开仓库或网盘分享链接。

### 更新 latest

1. 等待队列处理完成并做完整备份。
2. 拉取镜像并强制重建容器。
3. 检查状态、日志和健康接口。

```bash
docker compose pull
docker compose up -d --force-recreate
docker compose ps
docker compose logs --tail=100 easynotice
curl http://127.0.0.1:18088/health
```

最后一条按默认宿主机端口 18088 举例；若端口映射是 `28088:18088`，这里使用 `127.0.0.1:28088`。

`docker compose restart` 不会下载新镜像，因此不算更新。老 NAS 如果使用 Compose v1，可把命令写成 `docker-compose`。

官方镜像支持 `linux/amd64` 和 `linux/arm64`，不提供 32 位 ARMv7 镜像。

### 固定版本

`latest` 会随主分支更新。更看重可控性时，从 [Releases](https://github.com/xudong7587/easynotice/releases/latest) 选择一个版本，把镜像改成：

```yaml
image: ghcr.io/xudong7587/easynotice:vX.Y.Z
```

### 恢复备份

1. 停止容器。
2. 把当前 `data` 重命名保留，不要直接覆盖唯一现场。
3. 恢复备份中的完整 `data` 和匹配的 Compose。
4. 如果使用 `EASYNOTICE_SECRET_FILE`，恢复同一个外置密钥文件和挂载路径，不能生成新值。
5. 检查目录权限后启动。
6. 查看日志和 `/health`，再发送测试预览。

不要在程序运行时手工编辑 SQLite 数据库。

### 安全回退

只把镜像标签改旧、却继续使用已被新版本升级过的数据库，不保证兼容。安全做法是同时恢复升级前的完整 data，再使用当时的固定镜像标签。

`docker compose down` 不会删除 bind mount 的 data；如果改用 Docker 命名卷，绝对不要随意执行 `docker compose down -v`，它会删除卷。

### 磁盘占用

当前没有通知记录自动保留期。通知和投递记录会持续增长，请监控 data 占用，并从页面删除不再使用的图片。不要直接删除数据库行。

## 反向代理与公网访问

### 什么时候不需要公网

如果所有通知来源都在家里局域网，而出口只需 EasyNotice 主动访问企业微信或 Telegram，管理页和入口通常不必直接暴露公网。优先使用 VPN 或局域网访问。

需要公网地址的典型情况：

- 公网外的来源要主动调用 EasyNotice；
- 企业微信启用接收消息与事件回调；
- Bark 官方服务器要读取 EasyNotice 的本地图片。

### 反向代理的目标地址

- 代理程序直接运行在 NAS 宿主机：代理到 `127.0.0.1:宿主机映射端口`，默认是 `127.0.0.1:18088`。
- 代理也运行在 Docker 容器：它的 `127.0.0.1` 是代理容器自己；应使用共享网络中的 `easynotice:18088` 或 NAS 局域网 IP。

代理应传递 `Host`、`X-Forwarded-Host` 和 `X-Forwarded-Proto`。全程通过 HTTPS 访问时，在 Compose 中添加：

```yaml
environment:
  EASYNOTICE_COOKIE_SECURE: "true"
```

只在浏览器始终使用 HTTPS 时启用。若仍通过 HTTP 局域网地址登录，Secure Cookie 不会被发送，表现为登录成功后又回到登录页。

### 内外地址冲突

某些路由器不支持 NAT 回环：公网域名从外网可用，OpenWrt 在内网却打不开。可选办法：

- 在内网 DNS 中把同一域名解析到 NAS 局域网 IP；
- 让路由器和容器使用局域网地址，只让回调或 Bark 图片使用公网域名；
- 在原应用中手工替换入口 URL 的主机部分，保留 `/hook/随机令牌` 路径不变。

## 排查问题

### 先做五项检查

```bash
docker compose ps
docker compose logs --tail=200 easynotice
docker port easynotice 18088
curl http://127.0.0.1:18088/health
curl http://NAS局域网IP:18088/health
```

依次判断：容器是否运行、第一条报错是什么、端口是否映射、NAS 本机是否健康、其他局域网设备是否能访问。

上面的 `docker port` 查询容器内部 18088，保持不变；两个 curl 使用宿主机映射端口，若配置为 `28088:18088` 就把 curl 中的 18088 改为 28088。

### 局域网打不开但反向代理能打开

先从局域网电脑打开：

```text
http://NAS局域网IP:18088/health
```

根据结果区分两类问题：

- 能看到 `{"status":"ok"}`，但 `http://NAS局域网IP:18088` 是空白页：执行 `docker compose pull` 和 `docker compose up -d --force-recreate`，确认使用 GitHub 最新正式 Release 对应的镜像，再用无痕窗口打开。早期镜像的安全响应头会让浏览器把 HTTP 页面中的 JS、CSS 错误改成 HTTPS；当前版本已移除这项错误升级，不需要给局域网端口配置证书。
- `/health` 也无法连接：这是端口或网络链路问题，继续检查下面各项。

- Compose 是否为 `18088:18088`，而不是只绑定 `127.0.0.1`；
- `HOST` 是否为 `0.0.0.0`；
- NAS 防火墙是否放行 TCP 18088；
- 电脑是否在访客 Wi-Fi，AP 隔离是否开启；
- VLAN/ACL 是否禁止访问 NAS；
- 多网卡 NAS 是否使用了错误 IP。

外网反代能开，只证明反向代理到容器这条路可用，不证明局域网设备能直接进入 NAS 的 18088 端口。修复后的局域网管理页仍使用普通 HTTP；HTTPS 反向代理不受影响。

### 容器反复重启并报 uploads 权限错误

先更新并重建镜像，检查挂载不是只读、Compose 没有 `user:`。本地磁盘目录必要时可由 NAS 管理员把所有权改为 UID 1000；目录建议 700、文件 600。

NFS root-squash、SMB/CIFS 和特殊 ACL 可能禁止容器启动脚本修改所有权。SQLite 还依赖可靠的文件锁，不建议把 data 放在 SMB/NFS；优先迁到 NAS 本机磁盘或 Docker 命名卷。

### 端口已被占用

看到 `port is already allocated` 时，只改映射左侧，例如 `28088:18088`。容器端口、`PORT` 和健康检查继续使用 18088。

### 企业微信应用报 60020

把错误详情中的公网 `from ip` 加到“应用管理 → 自建应用 → 开发者接口 → 企业可信 IP”。公网 IP 再次变化后需要更新，或依靠企微群机器人补位。

### 企微机器人为什么没有图片

这是当前设计，不是配置错误。群机器人固定发送纯文字，不会使用入口图片、规则图片或默认封面。需要图文请用企业微信应用或 Telegram。

### Telegram 发送失败

检查 Bot Token、Chat ID、Bot 是否已经收到过消息，以及频道中是否有足够权限。再确认 NAS 容器能解析并访问 API 地址。若使用自定义 API 地址，只使用可信代理。

### Bark 收到文字但没有图标

文字由 EasyNotice 主动推送，图标却要由 Bark 服务端反向访问图片 URL。确认“其他容器访问地址”是公网可达的 HTTPS 地址，并从外网测试签名图片链接。

### 原应用显示成功，通知记录却为空

检查是不是发到了另一个旧地址、入口是否停用、OpenWrt 是否完整粘贴并保存应用、原应用所在设备是否能访问生成地址。查看反向代理和原应用日志，不要只看浏览器是否能打开管理页。

### 通知进入记录但手机没收到

打开详情看每个出口错误：

- 没有投递步骤：没有勾选可用出口；
- 同一出口两次失败：自动重试也失败，按具体错误检查凭证或网络；
- 后续出口“跳过”：前一个出口已经成功；
- 主出口失败、备用成功：状态会显示备用送达。

### 识别出的标题或正文不对

展开“原始 Webhook 数据”，查看原应用实际字段。敏感字段会尽力脱敏。可以修改原应用模板，或按原始路径使用 `{{ data.title }}` 等样式规则。

### 修改访问地址后，原应用仍使用旧地址

系统设置只改变以后生成和显示的地址，不会远程修改 Lucky、OpenWrt 等程序。回到每个原应用手工替换地址。

### 通知长期卡在正在发送

先等当前外部请求完成。如果容器曾异常退出，一条 `processing` 记录超过 5 分钟后，再重启一次服务，启动恢复逻辑会把它退回等待队列。备份和更新前应先等队列为空，因为停止时不会无限等待正在进行的外部请求。

### 数据库 locked 或 disk I/O error

检查磁盘是否已满、目录权限和底层文件系统；SMB/NFS 的锁与一致性可能不适合 SQLite，迁回本地磁盘后从完整备份恢复。

### HTTPS 反代后登录循环

确认浏览器始终使用 HTTPS、代理传递 `X-Forwarded-Proto`，并正确设置 `EASYNOTICE_COOKIE_SECURE=true`。如果仍需从 HTTP 局域网地址访问，则不要启用 Secure Cookie，或统一改用 HTTPS。

## 安全说明

### 首次启动不要直接暴露公网

空数据库的首次设置页需要创建第一个管理员。先在可信局域网完成初始化，再配置反向代理和访问控制，避免别人抢先设置密码。

### 哪些内容会加密

- 渠道配置和密钥；
- AI 配置和 API Key；
- 入口随机令牌；
- 脱敏后的原始请求与企微回调原文。

这些内容使用 AES-256-GCM 加密；管理密码使用 bcrypt 保存。登录连续失败会被短暂限流，但这不能代替 HTTPS、VPN、反向代理访问控制或防火墙。

### 哪些内容是可搜索明文

通知标题、正文、来源、事件类型和状态需要用于页面搜索，会以可查询形式保存在数据库中。不要把密码、完整 Token 或 Cookie 放进通知标题和正文。自动脱敏只是尽力而为，不能替代正确的使用习惯。

### 入口地址等同密钥

随机令牌位于 URL 中，可能进入原应用日志和反向代理访问日志。不要公开截图；发现泄漏时在入口详情点击“更换接口密钥”，旧地址会立即失效，随后更新原应用。

### installation secret

默认让 EasyNotice 自动创建 `data/.installation-secret` 最简单可靠。需要外置主密钥时可用 `EASYNOTICE_SECRET_FILE`，文件内容至少 32 个字符且容器 UID 1000 可读。

**既有安装不能随便换新主密钥。** 迁移到外置文件时，必须复制原 `data/.installation-secret` 的原始内容；使用新值会导致已有密文无法解密。不要优先使用 `EASYNOTICE_SECRET` 环境变量，因为它更容易从 Compose 或容器检查信息中暴露。

### 公开图片

带签名的素材地址没有自动到期时间，并可能被缓存一天。在素材被删除前，拿到链接的人可以访问它。不要把证件、内网截图或含密钥的图片用于 Bark 公网图标。

### 最终检查清单

- [ ] 管理页使用独立强密码，首次初始化未直接暴露公网。
- [ ] `data` 位于持久、本地、可备份的目录。
- [ ] 已做一次包含 `.installation-secret` 或原外置 secret 文件的完整恢复演练。
- [ ] 每个入口地址没有出现在公开截图或仓库。
- [ ] 最重要入口使用了至少一个已测试的备用出口。
- [ ] 企微应用的可信公网 IP 已核对。
- [ ] OpenWrt PushBot 使用的是 EasyNotice 生成的完整配置。
- [ ] 真实通知没有误带密码、Token、Cookie 或敏感图片。
- [ ] 更新前会等待队列为空，并先做完整备份。

如果仍无法判断问题，请在 [GitHub Issues](https://github.com/xudong7587/easynotice/issues) 提供：应用名称和版本、打码后的配置页、EasyNotice 通知记录状态、出口错误详情，以及容器日志的第一条相关错误。不要上传真实入口地址或任何密钥。
